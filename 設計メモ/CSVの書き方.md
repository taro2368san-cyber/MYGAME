# CSVの書き方

プログラムで読みやすくするための決まり。

## 1. 1行に1件、1列に1つの意味

- 1行目は見出しだけ。2行目からがデータ
- 空の行・空の列を残さない（最後の空行も消す）
- 1つのセルに2つの情報を入れない（「ポケモン：レベル」などは列を分ける）

## 2. 先頭の列は英字の id

- `rival_silver`、`ev_drop_100` のように、英小文字・数字・アンダーバーだけ
- イベントにかかわるもの（イベント本体、バトル相手、文言キー）は `ev_` で始める
- 一度決めた id は変えない。名前や文言を直しても id は変えない
- 他の表から参照するときは id を使う

## 3. 数値の列には数字だけ

- `%` や `円`、`マス`、`回目` を付けない。単位は見出しに書く（`発生率(%)`、`Lv1`）
- 「なし」は書かずに空欄にする

- 1つのセルに複数の値を入れたいとき（ミクリが解放する3つの職業など）は `|` で区切る。この書き方は「値」の列だけに使う

## 4. 選ぶ語は決まった語だけ

効果の型や条件の種類は、自由に書かず決まった語から選ぶ。表記がぶれるとプログラムが読めない。

| 列 | 使える語 |
|---|---|
| 効果の型 | 所持金の増減／アイテムの取得／強制移動・追加で進む／回復・手持ち全回復／バトル／職業の解放／博物館（イベントマスだけ。化石を預けて孵す、3.2.2） |
| 条件の種類（ライバル） | 御三家を選んだ人がいる／どれにも当てはまらない／いつも |
| 条件の種類（イベント） | バッジの数／図鑑の登録数（値以上なら満たす）／道具を渡す（値の道具を持っていれば満たし、その道具を渡してなくなる。例：サファリゾーンの園長に 金の入れ歯）／このマスの所有者（今いるマスの持ち主が自分。値は空） |
| 条件の種類（ショップの品） | 経過した週の数（その週以降に並ぶ） |
| ポケベル | ○（ポケベルで呼べる）／× |
| 状態 | 確定／案／仮／未定。**未定の行はゲームが読み飛ばす** |

新しい語が必要になったら、この表に足してから使う。

## 5. 名前は他の表と完全一致

場所名は「エリア」シート、ポケモン名は「ポケモン」シート、アイテム名は「アイテム一覧」と1文字も違わないこと。

## 6. 長い文章は文言の表へ

- セリフのように改行が入る文章は、セルに直接書かない
- `イベント文言.csv` に1行＝セリフ1行で書き、イベント側には `文言キー` だけ書く
- 場面ごとのセリフは、キーの後ろに付ける語で分ける

| 付ける語 | 場面 |
|---|---|
| なし | 最初に話しかけてくる |
| `_yes`／`_no` | 選択肢で「はい」「いいえ」を選んだ |
| `_win`／`_lose` | バトルでプレイヤーが勝った／負けた |
| `_ok`／`_notyet` | 条件を満たしている／満たしていない |

- `{トレーナー}` `{報酬}` `{アイテム}` `{職業}` `{名前}` は差し込み記号。ゲームが実際の名前に置き換える

**条件でセリフを1行だけ変えたいとき**

同じ「キー」と「順番」の行を2つ置き、片方にだけ「条件の種類」「条件の値」を書く。ゲームは、条件を満たす行があればそれを使い、なければ条件が空の行を使う。

| キー | 順番 | 話す人 | 文言 | 条件の種類 | 条件の値 |
|---|---|---|---|---|---|
| ev_giovanni | 2 | サカキ | おもしろい 目を している | | |
| ev_giovanni | 2 | サカキ | またお前か、まぁいい | バッジの数 | 8 |

バッジ8個（トキワジムでサカキを倒した後）なら下の行、それ以外は上の行が出る。イベントそのものが起きるかどうかには影響しない。

## 7. 条件は「種類」と「値」に分ける

「チコリータを選んだプレイヤーがいる」は、`条件の種類＝御三家を選んだ人がいる`、`条件の値＝チコリータ` の2列にする。複数当てはまるときは `優先` の小さいものを使い、どれにも当てはまらないときの行を `優先＝9` で必ず1つ用意する。

## 8. 文字コード

UTF-8（BOM付き）で保存する。Excelで「CSV UTF-8」を選ぶとこの形式になる。

## ライバル.csv（仕様書11.5）

- 1行が1人のライバル。`場所` のライバルマスに止まると、そのライバルとフルバトル。手持ちは ライバル_手持ち.csv（`ライバルid` で結ぶ。`条件の種類`／`条件の値` に合う行のうち `優先` の小さいもの。「いつも」か「どれにも当てはまらない」の行を1つは入れる）
- 勝って持ち主になると、`交換ポケモン1〜2` を `交換Lv` でもらえる（1人1回ずつ）。渡す子のコストは もらう子のコスト×調整値 rival_trade_cost（持ち主は rival_trade_cost_owner）。持ち主でなければ通信ケーブルも要る

## ロケット団拠点.csv（仕様書11.3）

- 1行が拠点の品1つ。`拠点id`（rb_mtmoon など）が同じ行は同じ拠点。拠点は `場所` でロケット団マスと結び付く
- `型`：買う／もらう／交換。`種類`：アイテム／ポケモン
- `価格`と`所有者の価格`（空なら 価格×調整値 owner_discount）。交換は`必要なコスト`（渡す子のコストがこれ以上）
- `Lv`：もらう・買うポケモンのレベル（種類がポケモンの行は必須）
- `回数` に何か書くと「1人1回」。空なら何度でも
- 拠点のセリフは イベント文言.csv の `ev_rocket_○○`（○○は拠点idの rb_ を取ったもの）。`_used`（1人1回の品を使い切った）、`_curse`（のろい解き）、`_trade`／`_trade_ok`（交換）
- 団員とのバトルの相手は トレーナー.csv の `種類＝ロケット団`（マスが空なら場所で探す）。なければ場所の野生の最高Lv＋1
