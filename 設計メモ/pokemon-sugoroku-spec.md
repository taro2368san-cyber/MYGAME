Unity製、ドカポン・ザ・ワールドをベースにしたポケモン題材のすごろくゲーム。

本書は相談で確定した内容をまとめたもの。各項目に状態を付記する。

- **確定** … 決定済み
- **案** … 提案段階。未承認
- **未定** … 未着手

判断に迷う仕様は、原則としてドカポン・ザ・ワールドに準拠する。（確定）

### 1.0 コンセプト（確定）

本家のポケモンでは、自分の手持ちへの愛着が他の人に伝わりにくい。このゲームでは、ゲームとしての楽しさに加えて、**自分の旅と相手の旅を並行して進めることで、相手のバックグラウンドが分かる**ことを目指す。

誰がどのポケモンを最初に選び、どこで捕まえ、どう育て、どこで助けられたか。同じ盤面で同時に旅をすることで、それが互いに見える。仕様に迷ったときは、この考え方に沿うほうを選ぶ。

### 1.2 中断と再開

途中保存を行う。（確定）週数200では8時間を超えるため必須。

- **セーブ枠は3つ**（確定）
- 保存のタイミング：週の終わりに自動保存し、加えて手番の切れ目で手動保存もできる（確定）
- タイトル画面の「つづきから」を選ぶとセーブ枠の一覧が出る。各枠には以下を表示する（確定）

| 表示 | 内容 |
|---|---|
| 保存日時 | 最後に保存した日時 |
| 次の手番 | 再開したときに最初に操作するプレイヤー |
| 週 | 何週目か（全体の週数も並べて「23／50週」のように出すと分かりやすい） |
- 保存する内容：盤面上の位置、所持金・アイテム・ポケモン、マスの所有者、週数、天候と残り週数、発生中の週イベント、状態異常、職業、各プレイヤーの累計（討伐数、図鑑など）、**旅の記録（1.5）**。旅の記録を保存し忘れると、中断・再開したゲームのエンドロールが途中からになるので注意

移動の途中やバトルの途中では保存しない。（確定）手番と週の切れ目だけに限ることで、保存と復元の処理が単純になる。

### 1.4 CPUプレイヤー

今は入れず、後から足す。（確定）

CPUは「プレイヤーの代わりに命令を出す役」として作る。人間がコントローラーで命令を出すのと同じ入口から、CPUが命令を出すだけなので、ルールや処理役には手を入れずに追加できる（15章の構造による）。

判断の作り方は、最初は単純な決まりの積み重ね（ルールベース）で十分。例：

- 移動先は、到達できるマスのうち「ジム＞ライバル＞アイテム＞草むら＞空マス」の優先順で選ぶ
- バトルでは、相手の弱点を突けるポケモンがいればそれを出す。いなければレベルが一番高いポケモン
- HPが半分を切ったら回復アイテムを使う

最初から賢くする必要はなく、遊びながら決まりを足していけばよい。

### 1.5 ゲーム終了とエンドロール

コンセプト（1.0）の締めくくりとして、ゲームの最後に**各プレイヤーの旅をエンドロールで流す**。（確定）互いの旅を振り返り、「この子、ここで進化してたんだ」と知る時間にする。

**流す内容**（案）

プレイヤーごとに、次の順で流す。

| 項目 | 例 |
|---|---|
| はじまり | キャラクター、名前、最初に選んだポケモン |
| 旅の年表 | 週と場所つきで、初めての捕獲、バッジの取得、進化、職業に就いた、ロケット団やライバルを倒した |
| 名場面 | 絆による回避（7.18）で踏ん張った場面、レベル追いつきの逆転、引き分け |
| 最後の手持ち | 3体それぞれの**出会った場所**とレベル、もちもの。一番長く手持ちにいたポケモン（確定：手持ちと出会った場所を振り返る） |
| 旅の数字 | 歩いたマス数、バトルの数、図鑑の登録数 |

**旅の記録の残し方**（案）

15.5の「結果」のうち、エンドロールに使うものを、プレイヤー・週・場所・ポケモン名つきで保存していく。命令の記録（15.9）から計算し直すより、起きたときに直接残すほうが単純。

- 記録するもの：捕獲、進化、バッジ取得、職業への就任、ロケット団・ライバル・ジムの撃破、絆による回避、レベル追いつき、引き分け
- **ポケモンごとの出会いの記録**（確定）：仲間になったときに、出会い方・場所・週を記録しておく。エンドロールで「今の手持ちとどこで出会ったか」を振り返るため
- 出会い方の種類（案）：最初のポケモン、捕獲、プレイヤー間の交換、ライバルマスでの他地方交換、ロケット団拠点での購入（化石・ポリゴン）
- 交換で来たポケモンは、「〇〇さんから受け取った」と元の持ち主も表示する（案）。互いの旅が交わった跡が残り、コンセプトにも合う
- 出会ったときの姿も記録する（案）。進化していれば「出会ったときはヒトカゲだった」と見せられる
- 「一番長く手持ちにいた」を出すため、ポケモンごとに手持ちにいた週数を数える。「先頭にして20ターン経過」の進化条件で使う数え方と同じ仕組みでよい

**順番**（確定）：結果発表 → エンドロール。順位が決まって一区切りついた後、余韻として旅を振り返る。映画のエンドロールに近い形。

**長さ**（確定）：1人あたり1分前後。4人なら4〜5分。○で早送り、スタートでスキップできるようにする（案）

## 2. 勝利条件

最終的な勝利ポイント（p）の合計が最も多いプレイヤーの勝ち。（確定）

ポイント源は2系統。（確定）

### 2.1 グランドルール

毎ゲーム固定で適用される配点。例として以下。（例示、数値は未定）

- バッジ × 5p
- 1,000円 → 1p（特殊NPCから購入）
- ロケット団最多討伐賞 … 20p（ゲーム終了時に、討伐数が最も多いプレイヤーへ1回だけ付与）（確定）

ロケット団マスはバトルで奪い合えるため、討伐のたびにポイントを与えると、2人で同じマスを往復して奪い合うだけで際限なく稼げてしまう。最多討伐者への一括付与にすることで、1ゲームで得られるロケット団関連のポイントは最大20pに収まる。討伐数そのものは奪い合いでも増えるため、「最多討伐」をめぐる競争として機能する。

最多討伐が同数の場合は、該当者全員に20pずつ付与する。（確定）

### 2.2 イベントルール

ゲーム開始前に目的を決定する。ランダム選出も可。（確定）

例として以下。（例示）

- 最終トーナメント優勝 … 30p
- 図鑑を埋めた数に応じて加算
- 最も多くの種類を捕まえた

### 2.3 検討事項

- 3つ目の系統（特殊ルール）は一旦なしとする。（確定）
- 金→ポイント変換：**最後の10週はポイント交換NPC（換金所）を閉鎖する**。（確定）終盤に貯めた金を一気にポイントへ換える逃げ切りを防ぎ、最後まで金の使い道を残す
- イベントルールは最初から全員に公開する。（確定）
- 週数設定が長いほど資金稼ぎが有利になるため、週数ごとの配点テーブルを持たせる。（案）

### 3.2.1 研究室

オーキド博士のいるマサラタウンのイベントマス。（確定）

| 内容 | 条件 |
|---|---|
| ポケモンセンターと同じ役割（回復、控えとの入れ替え、もちものの着脱、職業の変更） | いつでも |
| 職業「けんきゅういん」の解放 | 図鑑に130種類以上登録されている状態で止まる |
| 進化サービス：100,000円で、進化に必要なアイテムを揃えて進化させてくれる | 誰でも利用できる |

- 進化サービスの対象は、アイテムが必要な進化（いし、メタルプロテクターなど）と交換進化（確定）。レベル進化は対象外
- けんきゅういんは「進化に必要なアイテムを踏み倒せる」職業なので、この進化サービスの無料版にあたる。10万円の支払いは、けんきゅういん以外のプレイヤーが同じことをするための値段になる
- 初期所持金500円に対して10万円はかなり高額で、終盤の資金の使い道として機能する

交換進化を対象に含めるため、交換進化の経路はライバルマスと研究室の2つになる。ライバルマスの所有者は無料、非所有者は通信ケーブルで進化でき、研究室なら10万円で誰でも進化できる。通信ケーブルの解禁前でも、お金さえあれば交換進化ができる。

### 3.2.2 博物館（化石の孵化）

ニビシティに博物館のイベントマスを置く。（確定）おつきみ山のロケット団から化石を買い（11.3）、博物館に預けると、決まった週数のあとにポケモンに孵る。

```
おつきみ山（エリア2）で化石を買う
  ↓
ニビシティ（エリア1）の博物館に止まり、化石を預ける
  ↓ 3週たつ
もう一度博物館に止まると、孵ったポケモンを受け取る
```

| 項目 | 内容 | 状態 |
|---|---|---|
| 化石 | かいのかせき→オムナイト、こうらのかせき→カブト、ひみつのコハク→プテラ | 確定 |
| 化石の袋 | ポケモンの道具 | 案 |
| 孵るまで | 預けてから3週 | 案 |
| 受け取り | 孵った後に、預けた本人が博物館に止まったとき | 案 |
| 孵ったときのLv | 預けた人の手持ちの最高Lvから−5（最低Lv5） | 案 |
| 預けられる数 | 1人1個まで | 案 |

- 預けている間は袋が空くので、他のアイテムを持てる
- 化石を手に入れるにはバッジ1個（エリア2）が要り、孵すにはエリア1に戻る。行って戻る小さな旅になる
- 本家の化石は低いレベルで復元されるが、このゲームでは進み具合に合わせて手持ちの最高Lvから決める。そのままLv5だと終盤に孵しても使えないため
- 孵るまでの週数とLvの差は調整値シートで変えられる
- 預けた化石と受け取りまでの残り週数はゲーム状態として保存する。エンドロールの出会いの記録は「ニビ科学博物館で目覚めた」になる

### 3.3.1 ジムトレーナー（確定）

ジムのある町には**ジムトレーナーのマスを3つ**置く。ジムトレーナーを倒すと、そのジムに挑めるようになる。手持ちは `ジムトレーナー.csv` が正。

**トキワジム**：トキワジムはバッジ7個のプレイヤーにだけ出現する（3.3）。トキワのジムトレーナーも、トキワジムが出現しているプレイヤーだけがバトルできる。（案）解放の記録は他と同じく全員で共有。

**ゲーム状態**：ジムトレーナー24人それぞれの解放済みかどうかを、ゲーム状態として保存する（1.2）。

**盤面の置き方**：3人ともピッタリの出目で止まる必要があるので、ジムの手前のループ（3.1の盤面設計の指針）の上に置く。ループを回りながら3人を順に倒せる形にすると、何手番も足止めされにくい。

**見渡しモード**：ジムのマスの説明に「ジムトレーナー 2/3」のように、解放済みの人数を出す。

**データ**：ジムトレーナーのレベルは、ジムのエースのLvからの差（Lv差）で持つ。ジムのレベルを調整値で変えれば、ジムトレーナーも自動で付いてくる。

## 4. 移動

| 項目 | 内容 | 状態 |
|---|---|---|
| サイコロ | 0〜6。0は出にくい（調整値 dice_zero_rate、はじめは5%。ほかの目は同じ確率） | 確定 |
| 到達判定 | 直前のマスに戻らない歩き方で、出目ちょうどの歩数で着けるマスにだけ止まれる | 確定 |
| 逆走 | 直前のマスに戻る操作は「考え直し」として1歩取り消しになり、歩数は減らない。確定した移動経路に逆走は含まれない | 確定 |
| 通過マス | 効果を発揮しない。止まったマスのみ処理 | 確定 |
| 行き止まり | ピッタリの出目でしか止まれない。手前で止まることはなく、止まれるまで次の手番以降も振り続ける | 確定 |
| 「直前のマス」の範囲 | 1回の手番の中だけ。手番をまたぐとリセットされ、前の手番で来た道を戻る方向にも最初の1歩を進める | 確定 |
| 止まれるマスが1つもない場合 | 来た道を戻ってもらう。このときだけ折り返しも歩数として数え、出目ちょうどで止まれるマスを探す | 確定 |
| 行き先が1つの場合 | 自動移動はせず、必ず確認を挟む | 確定 |

### 4.1 移動の入力方式

以下2方式を両方実装し、プレイヤーが選べるようにする。（確定）

1. **ハイライト一括選択** … 到達可能な終点をすべて光らせ、行き先を1回で選ぶ。経路は自動で1本決定する
   - 表示は**光量で表す**（確定）。止まれるマスを光らせ、それ以外のマスはグレーにする。ルーレット4個（最大40歩）で止まれるマスが多くなっても、経路を1本ずつ描かずに済む
2. **1マスずつ選択** … 分岐のたびに進行方向を選ぶ

両者は同一の経路探索結果を使い、UIのみ差し替える。通過マスに効果がないため、経路を自動決定しても結果は変わらない。（確定）

**2つの方式で止まれるマスは必ず一致する**（確定）。1マスずつの方式では、戻った分は「考え直し」として歩数を使わない（4.1.1）。そのため、どれだけ寄り道や迷いをしても、最終的に止まれるのは「戻らずに出目ちょうどで着けるマス」だけになる。ハイライト方式は、その同じマスを最初から光らせて見せているにすぎない。

光らせるのは出目ちょうどで着けるマスだけで、行き止まりや未解放の境界の手前のマスは光らせない。（確定）

**止まれるマスがないときの処理**（確定）

1. まず「戻らずに出目ちょうどで着けるマス」を探す（通常）
2. 1つもなければ、折り返し（直前のマスへ戻ること）も歩数として数えて探し直す。ハイライト方式ではそのマスを光らせ、1マスずつ方式ではこのときだけ戻る操作が「考え直し」ではなく1歩として数えられる

ネットワーク状の盤面で一本道は少なく、さらに手番をまたぐと「直前のマス」がリセットされるため、2に進むことはまれ。小さな別マップで大きな出目が出たときや、未解放のエリアに囲まれた場所にいるときに起こりうる。

### 4.1.1 考え直し（1歩戻し）

1マスずつ選択の方式では、移動を確定するまで直前のマスに戻ることができる。戻った場合は**その1歩を取り消した扱い**となり、残り歩数は元に戻る。（確定）

例：出目3で A → B と進んだあと A に戻ると、A にいて残り3歩の状態に戻る。

- 何歩でも続けて戻れる。出発マスまで戻れば移動前の状態になる（確定）。ネットワーク状の盤面では分岐が多く、考え直しが頻繁に起きるため
- 戻れるのは直前のマスだけ。環状の道を回って以前通ったマスに再び入るのは通常の移動として歩数を使う
- 通過マスに効果がないため、取り消しても巻き戻す処理は発生しない。歩数と経路を戻すだけで済む

実装は、通った経路をスタックで持ち、直前のマスへの移動を検知したら1つ取り除くだけ。ハイライト一括選択の方式では、確定前に行き先を選び直せるため、この仕組みは不要。

### 4.1.2 海上マスとつり（確定）

**海上マス**：海や川の上のマス。「なみのり」を覚えたプレイヤーだけが入れる。覚えていないプレイヤーにとっては、未解放のエリアと同じく通れないマスとして経路探索から外す（3.3の実装上の扱いと同じ仕組み）。

**つり**：海上マスのとなりのマスにいるとき、準備フェーズで「移動」の代わりに「つり」を選べる。サイコロは振らず、その場から動かない代わりに、その場所の出現表の「つり」から野生のポケモンとバトルになる。（確定）

| 項目 | 内容 | 状態 |
|---|---|---|
| つりざお | 不要。海上マスのとなりなら誰でもつれる | 案 |
| バトル | 野生戦と同じ（クイック、先頭固定、ボールを投げられる） | 案 |
| つりの後 | その手番は終わる | 案 |
| なみのりの覚え方 | アイテム「ひでんマシン なみのり」を手に入れる（本家どおりサファリゾーンのイベント） | 案 |
| なみのり後の海上マス | 普通のマスと同じく移動でき、止まると出現表の「水上」から遭遇（草むらと同じ扱い） | 案 |

つりは「進まない」という代償があるので、行き先が悪い出目しか出ないときや、水のポケモンを狙いたいときの選択肢になる。

## 5. ターン進行と週

### 5.1 週の定義

各プレイヤーが1回行動したら1週進む。4人プレイなら1週＝4ターン。（確定）

期間を表す数値はすべて「週」で統一する。（確定）

### 5.2 フロー

```
週開始フェーズ
  └ 週イベント判定 / 収入処理
プレイヤーターン（手番順に人数分繰り返す）

  ├ 遭遇判定 → バトル呼び出し
  └ ターン終了
週終了フェーズ
  └ 週数を加算 / 終了条件の判定 / 順位の再計算
```

**準備フェーズ**（確定）

- アイテムの使用（自転車系など）。**1回の準備フェーズで1個まで**（確定）

1回休みのターンは準備フェーズも含めてスキップする。（確定）

週の切り替わりは最終プレイヤーのターンが完全に終了してから行う。移動中・バトル中に週を進めない。（確定）

**先頭が戦闘不能のとき**：先頭固定のバトル（野生、トレーナー、職業トレーナー）で先頭が戦闘不能なら、代わりに出すポケモンをプレイヤーが手動で選ぶ。（確定）

**レベル上限は本編と同じ100**。（確定）進化条件も本編準拠で自動的に決まるため、手打ちするデータが1フィールド減る。上限100なら週数200設定でも天井に届きにくく、終盤までレベル差が残るのでレベル追いつき機構（7.9）が最後まで機能する。

手持ちと控えを分けたことで、強いポケモンを控えに預けて守る（かわりに手持ちが弱くなる）というジレンマが生まれる。ポケモンセンターまで足を運ぶ手間がリスク管理のコストになる。

**種族データに必要な項目**（確定、xlsx の「進化条件」列で管理）


**進化の波及**

- コストが上がるため、交換で奪うには同等以上のポケモンを差し出す必要が生じる。育てた1体を守る手段になる
- 同時に狙われる価値も上がるため、攻守どちらにも働く
- 進化後の種は図鑑の別項目なので、進化させるだけで図鑑が1つ埋まる

進化を止める操作（本編のBボタンキャンセル）はない。進化させたくない場合は、もちもの「かわらずのいし」を持たせる。（確定、xlsx）ただし進化させないと低コストのまま高レベルという状態になり、相手が安いポケモンを差し出して奪えてしまう点に注意。

**進化アイテムの入手**：いし7種はタマムシデパートで買える。そのほかの進化アイテムの入手方法は xlsx の備考に従う。（確定、xlsx）

**交換進化**：初代の交換進化はフーディン、カイリキー、ゲンガー、ゴローニャの4種。本編では通信交換が必要なため、このゲームではライバルマス（11.5）と研究室の進化サービス（3.2.1）が進化の経路になる。

### 6.6 経験値

| 項目 | 内容 | 状態 |
|---|---|---|
| 設計目標 | 50週で2段階進化に到達できる程度 | 確定 |
| 分配 | 手持ち全員に入る | 確定 |
| 出場したポケモン | 1.0倍 | 確定 |
| 出場していないポケモン | 0.6倍程度 | 確定 |
| 控え | 経験値は入らない（経験値が入るのは手持ちのみ） | 確定 |
| カーブ | ゲームモード（週数設定）によって変えない | 確定 |

**0.6倍の意義**：出場した1体しか経験値が入らないと主力だけが育ち、相性が有利でもレベル差で選出できなくなる。弱点1.5倍が死ぬため、並走させる必要がある。

**控えが育たないことの意義**：強いポケモンを控えに預けて守ると、その間そのポケモンは成長しない。守るか育てるかのジレンマが生まれる。

**試算**（参考値）

- 50週 ＝ 各プレイヤー50ターン、うち15〜25戦
- 主力（よく出す1体） … Lv36前後。2段階進化に到達
- サブ2体 … Lv25〜28前後。1段階進化まで

**数式の出発点**（案）

```
必要経験値 = レベル³
1戦の獲得 = 係数 × 相手レベル²
```

同格の相手と戦い続けたとき、1戦あたり一定のレベルが上がる形になる。「20戦でLv5→36」に合わせると係数は4.6前後。この形なら200週でも80〜100に収まる。実際に遊んで係数1つで調整する。

**本編のカーブは使えない**：本編は数十時間のRPGを前提としており、そのまま使うと20戦程度でLv15前後にしか届かず、2段階進化が一度も見られない。「進化レベルは本編準拠、経験値の必要量は独自」と分けて考える。

## 7. バトル

### 7.1 基本構造

HPを削り合う複数ラウンド制。ドカポンを参考にする。（確定）

攻撃側と防御側が同時にコマンドを選び、その組み合わせで結果が決まる読み合い。サイコロは勝敗を決める主役ではなく、ダメージ式の末尾に乗る乱数として扱う。（確定）

```
バトル開始
  ├ お互いのポケモンを出す（選出）
  ├ すばやさを比べる
  └ 先攻・後攻のカードを伏せて並べ、1枚引く（7.1.2）
ラウンド
  ├ 攻撃側がコマンド選択
  ├ 防御側がコマンド選択
  ├ 相性表とダメージ式を適用
  └ 攻守を交代
どちらかのHPが0 → 終了
```

大枠で合意済み。

**1往復ごとに すごろくの番が変わる**（確定）：攻守が1往復したら（野生戦はボールの確認まで）、その人の番は終わる。次の自分の番は、サイコロを振らずにバトルの続きから始まり、決着するまでくり返す。

- プレイヤー同士のバトルとトーナメントは、2人の番が絡むので、今までどおり決着まで続ける
- バトルの途中の人がいるマスに止まっても、プレイヤー間バトルは起きない
- ラウンド上限（round_limit_quick／round_limit_full）は、番をまたいでも通しで数える

**テンポ目標**：クイックバトルは2〜4ラウンド、フルバトルは全体で6〜8ラウンドで決着すること。HPは低めに設定する。（案）1体あたり2〜3ラウンドで倒れる想定。

### 7.1.2 先攻・後攻の決め方（確定）

ドカポンと同じく、伏せたカードを1枚引いて先攻・後攻を決める。ただし、すばやさの速いポケモンほど先攻を引きやすいよう、カードの枚数と中身を変える。

**手順**

1. お互いのポケモンを出す（選出、または先頭）
2. すばやさを比べる
3. すばやさの差に応じて、先攻カードと後攻カードの割合を変えて伏せる
4. 仕掛けた側（NPC戦ならプレイヤー）が1枚引く

| すばやさの差 | 伏せるカード | 速い側が先攻になる確率 |
|---|---|---|
| ほぼ同じ | 2枚（先攻1・後攻1） | 50% |
| 速い側が少し上 | 3枚（速い側の先攻2・後攻1） | 約67% |
| 速い側が大きく上 | 4枚（速い側の先攻3・後攻1） | 75% |

- 有利な理由が画面で見える。カードが4枚並べば、すばやさで勝っているから先攻を引きやすいと分かる
- 上限を75%で止め、どんなに速くても後攻を引く可能性を残す。すばやさの命中補正を±10%に抑えたのと同じ考え方
- 「少し上」「大きく上」の境目はすばやさの比で決める。仮に1.2倍以上、1.5倍以上とし、調整値シートで変えられるようにする（案）
- 比べるのは、場に出たときの特性（ひでりなど）が発動した後の、天候・特性・もちものを含めたすばやさ（案）
- **フルバトルで交代したら、カードを引き直す**（確定）。倒れて次のポケモンを出したとき、レッドカードや脱出ボタンで入れ替わったときも含む。新しく出たポケモンどうしのすばやさで割合を決め直し、引いた結果から攻守の交互が始まり直す
- 引き直すときも、カードを引くのは仕掛けた側（案）

### 7.1.3 野生戦の捕獲タイミング（確定）

野生ポケモンとのバトルでは、**攻撃と防御が1往復終わるたびに「ボールを投げる？」の確認**を出す。

```
ラウンド（攻撃側）
ラウンド（防御側）
  ↓
ボールを投げる？
  ├ 投げる → ボールの種類を選ぶ → 捕獲判定（6.3）
  │           ├ 成功 → バトル終了
  │           └ 失敗 → 次の往復へ
  └ 投げない → 次の往復へ
```

- ボールを投げても、自分の攻撃の手番は消費しない。攻撃で削ってから投げる、という流れが1往復ごとに取れる
- 攻撃コマンドの「どうぐ」からボールを投げることはしない。投げる場所をここに一本化する
- 野生戦だけ。トレーナー戦やプレイヤー戦にはこの確認は出ない
- 理由：攻撃の手番を使って投げる形だと、削る・投げる・削る…で往復が増え、捕まえようとするほど長くマスに留まることになるため

**失敗したとき**（確定）：野生側に追加の攻撃は与えない。次の往復が通常どおり始まるだけ。

### 7.1.1 バトルの種類

2種類に分ける。（確定）

| 種類 | 内容 |
|---|---|
| クイックバトル | 1体のみで決着。手持ち3体から選出する |
| フルバトル | 手持ちを全て倒し切るまで。倒れたら次を選べる |

**選出の有無**（確定）

| バトル | 選出 |
|---|---|
| 野生、トレーナーマスのクイックバトル | なし。先頭が自動で出る |
| 職業トレーナー | なし。先頭が自動で出る（トレーナーマスの亜種のため） |
| ロケット団、プレイヤー同士のクイックバトル | 3体から選出 |
| フルバトル | 3体から選出。倒れたら次を選ぶ |

日常的な遭遇はテンポを優先して先頭固定、重要な戦いでは読み合いを残す、という分け方。タイプ相性の読み合いはロケット団・プレイヤー戦・フルバトルで効く。

**フルバトルの意味**

- 敗北すれば3体とも戦闘不能になるため、全滅＝最寄りのポケモンセンターへ強制送還（7.9）が自動的に適用される。追加ルールなしで最も重いペナルティになる
- 3体とも出場するため経験値が全員1.0倍。クイックの約1.5倍の効率になり、リスクを取って挑む動機になる

フルバトルの機会は最大17箇所（ジム8、ライバル7、サカキ、トーナメント）。1回が長いと全体が間延びするため、ラウンド数の目標を守ること。

**ラウンド上限と判定**（確定）

ラッキーやハピナスのように相手を倒す手段がほぼないポケモンどうしが当たると決着がつかないため、ラウンド数に上限を設け、超えたら判定で勝敗を決める。

| バトル | 判定の順番 |
|---|---|
| クイック | 1. 出ているポケモンの「現在HP÷最大HP」が高いほうの勝ち |
| フル | 1. 戦闘不能になっていないポケモンの数が多いほうの勝ち<br>2. 同数なら、手持ち全員の「現在HP÷最大HP」の合計が高いほうの勝ち |

それでも同じなら**引き分け**とし、2人とも1回休みになる。

- 判定で決まった勝敗は、通常の勝敗と同じに扱う（報酬・敗北ペナルティともに適用）（確定）
- 引き分けでは報酬も奪取も発生しない（確定）
- NPC戦の引き分けでは、プレイヤーだけが1回休みになる（確定）

**実数値の計算**（確定）：本家の計算式から、個体値・努力値・性格を除いた形を使う。小数は切り捨て。

```
HP     ＝ 種族値 × 2 × レベル ÷ 100 ＋ レベル ＋ 10
その他 ＝ 種族値 × 2 × レベル ÷ 100 ＋ 5
```

**必殺技の参照**：こうげきととくこうのうち、ステータスが高い方を使う。（確定）どのポケモンでも必殺が機能し、死に技になる個体が出ない。相手の種族値から必殺の系統を推測できるため、カウンターの読みが成立する。

僅差のポケモンは判別しにくいので、**バトル画面に必殺の系統を表示する**。（案）進化で系統が変わる個体もあり、育てると戦い方が変わる。

**すばやさの寄与制限**：すばやさは3つの役割を持つため、命中・回避への寄与は小さく抑える。すばやさの差が大きくても命中率が±10%程度しか動かないようクリップをかける。（確定）

**データ出典**：とくこう・とくぼうが分かれるのは金銀以降のため、初代ではなく現行作品の種族値を使う。どの世代を基準にするかを決めて記録すること。（未定）

### 7.5 ダメージ式（確定）

技名は盛り上げるための演出で、ダメージは**ステータスだけ**で計算する。技ごとの威力は持たない。（確定）

本家の割り算の形を下敷きにする。引き算の形（攻撃−防御）は、防御の高い相手にダメージが0になりやすく、硬いポケモンどうしで決着がつかないため採らない。

```
① 実効ステータス ＝ 実数値 × 能力ランク × 職業 × もちもの（ステータスを上げるもの）
                     ※攻撃側・防御側それぞれに計算する

② 基本ダメージ ＝（攻撃側のレベル ＋ 5）× 攻撃側の実効ステータス ÷ 防御側の実効ステータス ＋ 2

③ 最終ダメージ ＝ 基本ダメージ × コマンド倍率 × 弱点 × 急所
                  × 特性・もちもの（ダメージを上げるもの）× やけど × 乱数
                  （小数は切り捨て、最低1）
```

**使うステータス**：物理攻撃は「こうげき÷ぼうぎょ」、特殊攻撃は「とくこう÷とくぼう」、必殺技は攻撃側のこうげき・とくこうの高いほうと、それに対応する防御側の値。

**倍率の分け方**

| ①でステータスにかける | ③で最後にかける |
|---|---|
| 能力ランク、タイプ職・ステータス職、こだわりハチマキ、とつげきチョッキなど | ガードの成否（7.3）、弱点、急所、しんりょくなどの特性、いのちのたまなど、やけどの物理半減、乱数 |

職業と能力ランクは最後にかけるのではなくステータスにかける。タイプ職は防御側のぼうぎょ・とくぼうも上げるため、最後にまとめてかけると守る側の補正が抜け落ちる。

**「レベル＋5」の意味**：攻撃と防御は同じようにレベルで伸びるので、同じレベルどうしでは割り算の答えがほぼ変わらない。一方HPはレベルとともに増える。レベルの項がないと、序盤はほぼ一撃、終盤は5回以上の殴り合いになる。「レベル＋5」を掛けることで、どのレベル帯でも同格の相手に1回でHPの4割前後を与え、2〜4ラウンドで決着する長さに揃う。

| 同格どうし（種族値すべて80） | HP | 1回のダメージ | HPに対して |
|---|---|---|---|
| Lv10 | 36 | 17 | 約5割 |
| Lv30 | 90 | 37 | 約4割 |
| Lv50 | 140 | 57 | 約4割 |

使うのは攻撃側のレベル（本家どおり）。レベル差は実数値と「レベル＋5」の両方に効くため、育てたポケモンがはっきり強くなる。レベル追いつき機構（7.8）があるので、狩られる側にも逆転の目は残る。

**乱数**：攻撃ダイスの目で決め、1なら0.85倍、10なら1.00倍（本家と同じ幅）。

**調整できる数**：「＋5」「＋2」、最低ダメージの1は調整値シートで変えられる。全体のダメージを上げ下げしたいときは「＋5」を動かす。

### 7.11 タイプ相性

ポケモンカードを元にした簡易的な相性とする。（確定）

**タイプは11種**（確定）

```
種族データ
  ├ タイプ（攻撃時に使う。11種）
  └ 弱点タイプ（防御時に受ける。11種のうち1つ）
```

**未定**：特性の効果を型として整理すること。マス効果や職業補正と同じく、少数の型の組み合わせで表現できるはず。

### 7.13 天候

晴れ・雨・砂あらしの3種。（確定）

**発生源**

| 発生源 | 内容 |
|---|---|
| 週イベント | 雨季・乾季・すなあらしの日。各3週間継続 |
| アイテム | グラードン／カイオーガ／レックウザのふえ。各3週間継続 |
| 特性 | ひでり、アメフラシ、砂あらしなど、バトル中に発生 |

**効果**

- 砂あらしは闘タイプ以外に毎ターン最大HPの1/10のダメージ

**優先順位**：週イベントの天候とアイテム（三竜の笛）が重なった場合、**笛が優先**する。（確定）

**特性による天候**（確定）：ひでり、アメフラシ、すなおこしなどの特性で変えた天候は、**そのバトルの間だけ**フィールドの天候を上書きする。バトルが終われば週イベントや笛による天候に戻る。複数の特性がぶつかった場合は、後から出したポケモンの特性が勝つ（本編と同じ）。（案）

### 7.14 バトルのダイスと確率判定

バトル中に画面に出るダイスは**攻撃ダイス**だけ。（確定）攻撃のたびに1〜10を1回振り、ダメージ式の乱数（1で0.85倍、10で1.00倍）に使う。

それ以外の「〇〇%で起きる」効果は、すべて**プログラム内部の確率で自動判定**する。（確定）画面にダイスは出さない。

| 内部で判定するもの | 例 |
|---|---|
| 技の追加効果 | 20%で相手をどく、10%で相手のすばやさを1段階下げる |
| 特性 | はりきり（ガードされなかったとき20%で物理1.5倍）、ほのおのからだ（20%でやけど）、いやしのこころ（バトル終了時10%で手持ちの状態異常を治す）、せいでんき（30%でまひ） |
| 状態異常 | まひで動けない25% |
| 急所 | 通常5%、ピントレンズで15% |

確率の数値は xlsx（ポケモンシート、ポケモンの道具シート）に書いてあるものが正。1〜10のダイスでは表せない25%なども、そのまま使える。

### 7.15 能力ランク

ステータスを一時的に段階で上げ下げする仕組み。（確定）

| 項目 | 内容 | 状態 |
|---|---|---|
| 対象 | こうげき、とくこう、すばやさの3つ（ぼうぎょ・とくぼう・HPは対象外） | 確定 |
| 範囲 | −2〜＋2 | 確定 |
| 上がる側の倍率 | ＋1：1.5倍、＋2：2倍 | 確定 |
| 下がる側の倍率 | −1：2/3倍、−2：1/2倍 | 確定 |
| 持続 | バトル中のみ。フルバトルでは交代で0に戻る | 確定 |

範囲を本編の±6ではなく±2に絞るのは、バトルが2〜4ラウンドで終わるため。段階を積む余裕がないので、細かく刻んでも差が出ない。

**データでの使われ方**：いかく（相手のこうげき−1）、じしんかじょう（こうげき＋1）、ひらいしん（とくこう＋1）、でんきエンジン（すばやさ＋1）、くだけるよろい（接触攻撃を受けてガードに失敗したとき、すばやさ＋1）、弱点保険（こうげき・とくこう＋2）、しろいハーブ（下がったランクを戻す）。

### 7.16 ガード失敗時に発動する効果

### 8.1 枠の構成

### 8.3 妨害アイテム

| 項目 | 内容 | 状態 |
|---|---|---|
| 対象 | 任意の相手を狙えるが、同じエリア内に限る | 確定 |
| 位置づけ | ドカポンのフィールド魔法に相当 | 確定 |

この射程設定により、エリア分割が初めて戦術的な意味を持つ。同じエリアに固まると互いに手を出せる危険地帯になり、誰もいないエリアに移れば妨害から逃げられる。ただしファンは盤面に固定されているため、収入源のあるエリアには戻らざるを得ない。位置取りそのものが駆け引きになる。

実装は自分のいるノードのエリアIDを見て、同じIDのプレイヤーを列挙するだけ。

**射程の例外は作らない**：すべての妨害をエリア内に統一したため、エリアを越えて届くアイテムは作らない。（確定）同じエリアに誰もいないときは使えないが、トレーナーの道具枠がポケモンの道具枠と分かれているため、回復などの枠は圧迫しない。

### 8.9 売り買い

**売値は価格の半額**（確定）。端数は切り捨て。どのショップでも売れる。（案）

価格と売り買いの可否は xlsx が正。「アイテム一覧」と「ポケモンの道具」の両シートに、次の列を持たせてある。

| 列 | 内容 |
|---|---|

トレーナーの職業を導入する。職業マスでのバトルに勝つことで取得する（9.2）。（確定）

ドカポンの職業は熟練度を上げると上級職に進むが、**熟練度は省く**。職業は補正のセットのみを持つ。（確定）

### 9.1 分類

一覧と効果値は xlsx の「職」シートが正。

| 系統 | 数 | 効果 |
|---|---|---|
| タイプ | 11 | 手持ちの該当タイプのこうげき・とくこう・ぼうぎょ・とくぼうが1.3倍 |

### 9.2 取得経路

**職業の取得は「解放」と「選択」の2段階に分かれる。**（確定）

| 段階 | 場所 | 内容 |
|---|---|---|
| 解放 | 職業マス | 条件を満たした状態で止まるとバトルでき、勝利するとその職業が解放される。所有・非所有にかかわらず挑戦できる |
| 選択 | ポケモンセンター | 解放済みの職業の中から、就く職業を選ぶ・切り替える |

有効な職業は常に1つだけ。切り替えると前の職業の効果は消え、累積しない。解放済みの職業には何度でも戻れる。（確定）

解放した直後は、センターに行かずにその場で就くことができる。（確定）2回目以降の切り替えはセンターで行う。

解禁条件の型は3つの要素の組み合わせ。

| 要素 | 例 |
|---|---|
| バッジ数 | 4個以上（タイプ職）、6個以上（からておう・サイキッカー）、8個以上（エリートトレーナー） |
| 育成・収集の実績 | 該当タイプのレベル合計100以上、図鑑100種以上・130種以上 |
| 固有条件 | サカキ討伐後にシルバーとニューラまたはマニューラを交換しポケベルで再戦（ロケット団）、自転車を30回以上使用＋17番道路のトレーナー3人以上所有（サイクリング） |

**けんきゅういんの条件は経路で変わる**（確定）：オーキド博士（研究室、3.2.1）に会う場合は図鑑130種類以上、ポケベルでナナカマド博士を呼んだ場合は図鑑100種類以上に軽減される。

条件が段階的なため、職業の取得自体がゲーム中盤以降の目標になる。バッジ・図鑑・育成という既存の指標がそのまま条件に使われており、別の指標を増やしていない点が良い。

**職業マスはトレーナーマスの亜種**（確定）。新しいマス種別は作らず、トレーナーマスに「職業ID」のフィールドを1つ足すだけで表現する。所有権・年貢・回復ボーナスはトレーナーマスと同じ挙動になる。

職業への挑戦は所有・非所有にかかわらず可能。所有していても職業取得が有利になるわけではない。

**職業マスの配置**（確定）

| 職業 | 配置 |
|---|---|
| タイプ職（11種） | 職業ごとに3か所の候補地を決めておき、ゲーム開始時にそのうち1か所をランダムで選んで配置する。遊ぶたびに場所が変わる |
| けんきゅういん | マサラタウンの研究室（3.2.1） |
| だいすきくらぶ、からておう、サイキッカー、エリートトレーナー | 決まったトレーナーマスに固定 |
| ロケット団、サイクリング | 盤面には置かない。条件を満たすと解放される |

**タイプ職の候補地**（確定）：職業ごとに、その職業らしい場所を3か所ずつ選んである。一覧は xlsx の「職」シートの「配置候補」列が正。

例：つりびとは25番道路・12番道路・19番水道、やまおとこはおつきみ山・イワヤマトンネル・ディグダの穴、オカルトマニアはポケモンタワー・シオンタウン・ポケモン屋敷。

- 11職業33か所はすべて別の場所なので、ランダムに選んでも2つの職業が同じ場所に重なることはない
- 職業ごとに、エリア1〜3（バッジ5個未満でも入れる場所）に少なくとも1か所は候補を入れてある
- 盤面を作るときは、候補地それぞれにトレーナーマスを最低1つ置く必要がある

### 9.3 バッジとの棲み分け

- バッジ … 積み上げ型。捕獲しやすさのみ
- 職業 … 選択型。戦闘補正と盤面能力

バッジからステータス向上を外したため、戦闘補正は職業に一本化されている。

### 9.4 要注意事項

**ロケット団職の「コストに限らず人のポケモンを奪える」**は、交換のコスト制限（7.7）を丸ごと無効化する。解禁条件が非常に厳しいため狙って取るのは難しいが、取った人が一気に有利になる構造。この仕様のまま採用する。（確定）

あわせて、ポケモンセンターでの回復ができなくなる代償を負う。自分のファンマスでの回復（11.2）が生命線になるため、ファンを持たない状態で取ると詰みうる。

**センターで禁止されるのは回復だけ**（確定）。控えとの入れ替え、もちものの着脱、職業の変更は通常どおり行える。転職もできるため、ロケット団職から抜けられなくなることはない。

## 11. トレーナーと所有権

### 11.1 基本

トレーナーマスは所有権を持つ。倒すとそのトレーナーが自分のファンになり、配当時に年貢が入る。（確定）

ジムには所有権を持たせない。ジムは勝利ポイント源、トレーナーは収入源として役割を分ける。（確定）

### 11.2 トレーナーマスの挙動

| 状況 | 起きること | 状態 |
|---|---|---|
| 無所属のトレーナーに止まる | バトル。勝てばファンになる | 確定 |
| 自分のファンに止まる | 回復とアイテム（価値は少なめ） | 確定 |
| 他人のファンに止まる | お金を払って回復する。支払いは所有者の収入になる | 確定 |

他人のファンとのバトルによる奪取は行わない。（確定）

投資（強化）システムは入れない。（確定）

回復ボーナスにより、ファンの価値は収入だけでなく盤面支配になる。ファンを多く持つ人は回復地点が広がり、敵のファンだらけのエリアは金を吸われる危険地帯になる。ポケモンセンターとの棲み分けは、控えとの入れ替えができる点で保たれる。

支払いが所有者の収入になるため、ファンは年貢（7週ごと）と随時収入の二重の価値を持つ。

### 11.2.1 所有権の移動手段

ファンの奪取ルートは3つ。（確定）

| ルート | 性格 |
|---|---|
| 特定アイテムによる支配 | 狙い撃ち |
| ロケット団撃破の報酬（エリア内のトレーナーマス2つ） | ランダムで2つ |
| プレイヤー間バトルの勝利報酬 | 運（ランダムで1人） |

**支配アイテムがバランスの中心変数になる**。出やすければファンが頻繁に入れ替わり、出にくければ序盤に取った人が固定的に有利になる。

支配アイテムは「バトルサーチャー」（8.6）。推奨：ショップでは買えず、鍵付きボールマスやロケット団撃破の報酬から低確率。（案）

|---|---|---|

## 12. 下位プレイヤーへの救済

4人プレイでは1人が集中的に狙われると立て直せなくなる。何らかの補正を入れる。（確定）

**救済の内容**（確定）

| 条件 | 救済 |
|---|---|
| バッジ3個以上、連続20週最下位、トレーナーの道具枠に空きがある | 「なぞのチケット」がポケットに入る |
| バッジ6個以上、連続50週最下位 | ロケット団からスカウトが来る（ロケット団職が解放される） |
| 連続10週最下位 | モンスターボールマスで1段階上の表を引く（8.8.1） |

- バッジの条件があるため、何もせずに最下位でいるだけでは救済を受けられない。少なくとも序盤を進めた人だけが対象になる
- なぞのチケットは、最下位のまま持ち続けると不思議なチケットに変わる（xlsx の仕様）。救済が2段階につながる
- ロケット団職の通常の解禁条件（サカキ討伐後のシルバーとの交換、ポケベルでの再戦）とは別の入手経路になる
- 連続50週の条件は、50週設定のゲームでは成立しない。100週以上の設定でのみ起きる救済になる

**「最下位」の判定基準**（確定）：週終了フェーズで再計算する順位（5.2）は、次の合計で決める。

```
順位用ポイント = 所持ポイント ＋（所持金 ＋ 所持トレーナーマスの換算額）÷ 1,000
```

所持ポイントはその時点で確定しているもの（バッジ、換金済みのポイントなど）。お金とトレーナーマスは、グランドルールと同じ「1,000円＝1p」でポイントに換算する。ポイントに換えていないお金や、盤面に持っているファンも含めた「総合的な豊かさ」で最下位を決めることになる。

**マスの換算額**（仮で確定）：ロケット団マスも換算に含める。

| エリア | トレーナーマス | ロケット団マス |
|---|---|---|
| 1 | 500円 | 800円 |
| 2 | 800円 | 1,200円 |
| 3 | 1,200円 | 1,500円 |
| 4 | 1,500円 | 2,200円 |

テストプレイで見直す前提の仮の値で、xlsx の「調整値」シートでいつでも変更できる（13.6）。別マップ内のマスは、その別マップの親エリアの値を使う。（案）

## 15. プレイ形態と全体構造

### 15.1 方針

| 項目 | 内容 | 状態 |
|---|---|---|
| プレイ形態 | 1台のパソコンを交代で操作するローカルプレイで作る | 確定 |
| 将来の拡張 | オンライン対戦に移行できる構造にしておく | 確定 |
| 入力 | PS4コントローラーを2個つなぐ | 確定 |

ローカルとオンラインの違いは、ルールではなく「操作がどう流れるか」にある。ローカルでよくある「ボタンを押したらその場で盤面のデータを書き換える」作りにすると、書き換えがあちこちに散らばり、後からオンライン化するときにほぼ作り直しになる。

そこで、ローカルの段階から**操作を「命令」の形にして、1か所でまとめて処理する**作りにする。ローカルでは命令の送り先が自分自身、オンラインでは親の端末になるだけで、ルールの部分には手を入れずに済む。

### 15.2 4つの役割

| 役割 | 中身 | 例 |
|---|---|---|
| ゲーム状態 | ゲームのすべての情報を1か所にまとめたもの | 盤面、各プレイヤーの位置・所持金・アイテム・ポケモン、マスの所有者、週数、天候、乱数の状態 |
| 命令 | プレイヤーの操作を「誰が、何を、どの対象に」の形にしたもの | 「プレイヤー2が、キズぐすりを、1番スロットのポケモンに使う」 |
| 処理役 | 命令を受け取り、ルールに照らして確認し、状態を更新し、結果を出す | ルール全体（ダメージ計算、移動探索、マス効果など） |
| 表示 | 結果を受け取って、画面と演出に反映する | コマの移動アニメ、バトル演出、UI |

流れは常に一方向になる。

```
入力（コントローラー・マウス）
  ↓ 命令を作る
処理役
  ├ 命令が正しいか確認（だめなら拒否）
  ├ ゲーム状態を更新
  └ 結果を出す（何が起きたか）
  ↓
表示（画面と演出）
```

### 15.3 守る約束

実装中に崩さないための決まり。

1. **ゲーム状態を書き換えてよいのは処理役だけ。** 画面の部品や演出から直接書き換えない
2. **操作はすべて命令として処理役に渡す。** 「ボタンを押したら所持金を減らす」ではなく「アイテム購入の命令を出す」
3. **乱数は処理役の中だけで振る。** サイコロ、バトルのダイス、週イベントの抽選、ランダムな奪取先など、すべて。乱数の状態もゲーム状態に含めて保存する
4. **処理役は命令の正しさを確認する。** 手番でない人の命令、行けないマスへの移動、持っていないアイテムの使用、準備フェーズ以外での並び替えなどは受け付けない。ローカルではバグ防止、オンラインではずれや不正の防止になる
5. **処理役はUnityの画面部品に頼らない普通のC#で書く。** 画面がなくても動くので、テストしやすく、将来オンラインの親でもそのまま動かせる
6. **結果は「起きたこと」として表示に渡す。** 「サイコロの目は7」「プレイヤー1がマス45へ移動」「バトル開始」など。演出をどう見せるかは表示側が決める
7. **待ち時間をルール側に入れない。** 演出の終了を待つのは表示側の仕事。ルールは一瞬で処理を終える

### 15.4 命令の例

| 場面 | 命令 |
|---|---|
| 準備フェーズ | アイテムを使う、手持ちを並び替える |
| 移動 | サイコロを振る、行き先を決める、1歩進む、1歩戻す（考え直し）、移動を確定する |
| マス | ショップで買う、ポケモンセンターで回復・入れ替え・もちもの着脱・職業変更、ポイント交換、別マップに入る |
| バトル | ポケモンを選出する、攻撃のコマンドを選ぶ、防御のコマンドを選ぶ、交代する、ボールを投げる、逃げる、降参する |
| バトル後 | 勝利報酬を選ぶ（アイテム、ファン、ポケモン交換） |
| その他 | 妨害アイテムの対象を選ぶ、保存する |

### 15.5 結果の例

処理役が表示に渡す「起きたこと」の例。

- サイコロの目が決まった
- プレイヤーがマスを移動した
- マスの効果が発動した（所持金が増えた、アイテムを得た）
- バトルが始まった、ダメージが入った、状態異常になった、能力ランクが変わった
- ポケモンが倒れた、進化した、捕獲できた
- 所有者が変わった
- 週が進んだ、天候が変わった、週イベントが起きた
- ゲームが終わった

表示はこの列を順に受け取り、演出として再生する。

### 15.6 同時選択の扱い

バトルの読み合いでは、攻撃側と防御側のコマンドが**両方そろうまで処理役が待ち、そろった時点で同時に解決**する。

- ローカルでは、各自が手元のコントローラーで選び、画面には「選択済み」とだけ表示する。相手の選択は見えない
- オンラインでも同じ仕組みがそのまま使える。命令が別の端末から届くだけになる

### 15.7 フェーズの管理

処理役は現在のフェーズを1つ持ち、フェーズごとに受け付ける命令を決める。（5.2のターンフローと対応）

- 準備フェーズ：アイテム使用、並び替え、サイコロを振る
- 移動中：1歩進む、1歩戻す、行き先の確定
- バトル中：選出、コマンド選択、交代、降参など

フェーズに合わない命令は拒否する。「移動中にアイテムを使ってしまう」ような不具合を構造で防げる。

### 15.8 途中保存との関係

ゲーム状態が1か所にまとまっているので、**保存はそれを丸ごと書き出すだけ**になる。（1.2と対応）

- 乱数の状態も一緒に保存するので、再開後も同じ流れになる
- 保存はフェーズの切れ目でのみ行う。移動中やバトル中の中途半端な状態を保存しなくて済む
- 保存形式は未定（JSONなど、人が読める形式だとデバッグしやすい）

### 15.9 命令の記録（確定）

「開始時のゲーム状態」と「命令の列」を記録しておけば、同じ状況を何度でも再現できる。

- バグが起きたとき、その記録を流し直せば同じ場面が再現できる
- テスト用の場面（ロケット団戦の直前、200週の終盤など）を記録から作れる

### 15.10 ローカルで作るもの

- 手番の切り替え表示（「〇〇さんの番です」）
- コントローラーの受け渡しの指示表示（15.10.1）
- 同時選択時に、相手の選択を見せない画面
- 離れた友人と遊ぶ場合は、Parsecなどの遠隔操作ツールで代用する（案）。ローカル用のまま、友人が自分のコントローラーで参加できる

### 15.10.1 コントローラー2個の使い方

プレイヤーは最大4人だがコントローラーは2個なので、**コントローラーをプレイヤーに固定せず、場面ごとに役割で割り当てる**。（確定）

| コントローラー | 役割 |
|---|---|
| 1 | 手番のプレイヤー。移動、アイテム使用、マスでの操作、NPCとのバトルなどすべて |
| 2 | プレイヤー同士のバトルで、仕掛けられた側 |

これで足りる理由は、このゲームで同時に秘密の入力が必要になるのが**プレイヤー同士のバトルだけ**で、それは常に2人の対戦だから。同じマスでのバトル、突発バトルイベント、最終トーナメントのいずれも、1試合ずつ2人で戦う。

- バトルが始まるとき、画面に「〇〇さんは1、△△さんは2を持ってください」と表示して受け渡す
- 処理役は「この命令はどのプレイヤーのものか」をコントローラーではなく、そのときの割り当てで判断する。命令の中身は「誰が、何を」のままなので、オンライン化しても変わらない
- ゲーム開始時に、どちらのコントローラーを1にするかボタンを押して登録する

**実装メモ**：UnityのInput SystemはPS4コントローラー（DualShock 4）にUSB接続・Bluetooth接続とも対応している。開発中の確認用に、キーボードとマウスでも同じ操作ができるようにする。（確定）

### 15.11 オンライン化するときに追加するもの（将来）

以下は後から足せばよく、ゲーム状態と処理役には手を入れない。

- **通信**：命令を親に送り、結果を全員に配る
- **親の決め方**：1台が処理役とゲーム状態を持ち、他の端末はそれに従う
- **集まる仕組み**：部屋を作って参加する（Unity Relay・Lobby、Photonなどのサービスを使う）
- **切断と再接続**：抜けた人の手番をどうするか、戻ってきたときにゲーム状態を丸ごと送り直す
- **見せない情報**：他のプレイヤーのアイテムやコマンド選択など、相手に送らない情報の扱い

### 16.7 見渡しモード（確定、メニュー名は「探索」）

自分の手番の準備フェーズ（サイコロを振る前）に呼び出し、盤面を見て回る。

- カメラは平行移動と拡大・縮小ができる。回転はしない（カメラ固定の方針と揃える）
- マスを選ぶと、そのマスの名前、簡単な説明、現在地から何マスかを表示する
- 説明には、所有者がいれば誰のファンか、未解放のエリアならその旨も出す
- 距離の計算は移動の経路探索をそのまま使う
- **建物や洞窟（別マップ）の中は見えない**（確定）。見渡せるのは自分が今いるマップだけで、本マップからは別マップの入口までしか見えない。別マップの中にいるときは、その中だけを見渡せる
- そのため、別マップの中にいるシンボルエンカウント（ミュウツー、サンダー、ファイヤー、フリーザー）は、外からは見えない。入って初めて分かる
- 別マップの中にいる他のプレイヤーも、外からは見えない。順位画面などで「どのマップにいるか」までは分かる（案）

### 16.9 画面の遷移：手番の流れ（確定）

○で進み、×で1つ前に戻る。

```
手番開始
└ 準備フェーズ
   ├ 移動 → サイコロ（「○でサイコロを振る」と表示）
   │         ├ ×：準備フェーズへ戻る
   │         └ ○：サイコロを振る → 移動（ハイライト／1マスずつ）→ 行き先の確認 → マスの結果
   ├ アイテム → アイテム一覧（2つの袋）→ 使う相手を選ぶ → 確認 → 効果の表示 → 準備フェーズへ
   ├ 探索 → 見渡しモード（×で準備フェーズへ）
   ├ 入れ替え → 手持ち一覧 → 2体を選んで入れ替え → 準備フェーズへ
   │              └ 1体を選んで詳細 → 手持ちの詳細
   └ その他
       ├ 図鑑／職業／順位／イベントルール
       ├ 設定 → 音量、バトル演出
       └ セーブ → スロット1〜3 → 上書きの確認
```

- 移動を選ぶと「○でサイコロを振る」と表示し、○を押すまでは×で準備フェーズに戻れる。別の確認ダイアログは出さない
- サイコロを振った後は準備フェーズに戻れない（15.7のフェーズ管理と一致）
- アイテムを1個使った後は、準備フェーズのアイテムを選べない（グレー表示）

## 17. 体験・制作まわり（案：Claudeが決定。問題なければ確定）

### 17.1 デバッグ機能

開発用のビルドでだけ使える機能。キーボードのF1で開く。（案）すべて15章の「命令」として処理役に渡すので、通常の操作と同じ入口を通り、命令の記録（15.9）にも残る。

| 分類 | できること |
|---|---|
| 移動 | 好きなマスへワープ、出目を指定してサイコロを振る |
| 進行 | 週を進める、全エリア解放、バッジを付与、トキワジムの出現 |
| 持ち物 | お金・アイテム・ボールを付与 |
| ポケモン | 好きなポケモンを手持ちに追加、レベル変更、全回復、状態異常の付与 |
| バトル | 即勝利・即敗北、相手を指定してバトル開始 |
| 天候・イベント | 天候の変更、週イベントの発生 |
| 表示 | 見渡しの制限を外す（別マップの中も見える）、全マスのID表示、経路探索の結果表示 |
| 再現 | 乱数の種を固定する（同じ流れを何度でも再現できる） |

製品として遊ぶビルドには含めない。

### 17.2 文言の管理

画面に出る文字は、プログラムに直接書かず、xlsx の「文言」シートにキーで管理する。（案）

| 列 | 内容 |
|---|---|
| キー | プログラムが探す英字の名前（turn_start など） |
| 場面 | 手番、週、週イベント、通知、バトル、エンドロール、システム |
| 文言 | {トレーナー}{ポケモン}{週} などの差し込み記号つき |
| 備考 | 使う場面の補足 |

「バトル文言」シートを「文言」に広げ、手番、週イベントの告知、通知、エンドロール、システムのメッセージを足した。同じキーの文言を複数行置けば、ランダムに選ぶ（絆による回避と同じ）。マスの説明だけは、マスのデータ（description列）に持たせる。

### 17.3 データの版管理

- プロジェクト全体をGitで管理する（案）
- 正のデータは常に1ファイル。名前は版数を付けず `ポケモンゲームデータ.xlsx` に固定し、履歴はGitに任せる
- xlsxは中身の差分が見えにくいので、Unity用に書き出すCSVも一緒にコミットする。CSVの差分で「何が変わったか」が読める
- 共同で編集するときは、作業前に必ず最新を取ってから始める。同時に別々の人が同じxlsxを編集しない

### 17.4 異常時の扱い

| 起きたこと | 扱い |
|---|---|
| コントローラーの接続が切れた | すぐに一時停止し、「つなぎなおしてください」と表示。つながったら再開する。確定前のコマンドは捨てて選び直し |
| データの読み込みに失敗 | 起動時にデータを検証し、問題を一覧で表示して起動を止める。検証するのは、場所名・ポケモン名・キーの参照がそろっているか、出現率の合計が100か、マスのつながりが片方向になっていないか、など |
| セーブが壊れた | 保存は一時ファイルに書いてから置き換える（書き込み中に落ちても前のセーブが残る）。直前のセーブを1つ予備として残し、壊れていたら予備から再開できるようにする |

### 17.5 待っている人の体験

ローカルで1つの画面を全員で見るので、「他の人の番」も全員が見ている。その時間を、相手の旅を知る時間にする（1.0のコンセプト）。

- **他の人の大事な出来事は大きく見せる**：捕獲、進化、バッジ取得、ライバル撃破、絆による回避は、そのプレイヤーの色と名前つきで画面いっぱいに見せる
- **バトルはそのまま観戦できる**：特にプレイヤー戦と、ジム・ライバルのフルバトル
- **NPC戦の短い場面はテンポ重視**：野生やトレーナーのクイックバトルは演出を短めにする
- **自分に起きたことは自分の番でまとめて伝える**：他の人の番に妨害されたり、ファンを奪われたりした内容は、自分の手番の最初にまとめて表示する

### 17.6 演出

演出は○で早送りできる。設定の「バトル演出を短くする」をオンにすると、バトル中の演出が約半分の長さになる。（1.3）

| 場面 | 目安の長さ | 短縮時 |
|---|---|---|
| サイコロ | 1.5秒 | 同じ |
| コマの移動 | 1マス0.2秒 | 同じ |
| 先攻・後攻のカード | 2秒 | 1秒 |
| 技の演出 | 1.5秒 | 0.5秒 |
| ボールが揺れる（捕獲） | 2秒 | 1秒 |
| 絆による回避 | 2秒 | 2秒（短縮しない） |
| 進化 | 5秒 | 5秒（短縮しない） |
| バッジ取得 | 3秒 | 3秒（短縮しない） |
| 週イベントの告知 | 2秒 | 同じ |

絆による回避、進化、バッジ取得は旅の思い出になる場面なので、短縮の対象から外す。

### 17.7 見た目と音の素材

本家のゲームから抜き出した素材は使わない（14.1と同じ方針）。

| 対象 | 方針 |
|---|---|
| ポケモンの見た目 | まずはタイプの色の丸と名前のアイコンで作る。後から自作のイラストや自作の3Dモデルに差し替えられるよう、ポケモン名で絵を引く形にしておく |
| プレイヤーのコマ | キャラクターごとの色の駒 |
| 盤面 | 3.1のとおり。飾りは後から置く |
| BGM・効果音 | フリー素材を使う。魔王魂、DOVA-SYNDROME、効果音ラボなど。使う前にサイトごとの利用規約を確認する |

BGMは場面ごとに分ける：タイトル、エリアごとの盤面、野生戦、トレーナー戦、ジム・ライバル戦、伝説、エンドロール。

### 17.8 ルールの伝え方

- **ゲーム内の「あそびかた」**：その他メニューから、項目ごとに読めるヘルプ（移動、バトル、捕獲、ファン、職業、勝ち方）
- **はじめての場面でだけヒント**：初めての草むら、初めてのバトル、初めてのセンター、初めての妨害などで、1回だけ短い説明を出す。設定でオフにできる
- **紙1枚の早見表**：相性表（ガード）、勝利ポイントの内訳、ボタンの割り当てをまとめたものを、遊ぶ前に配る
